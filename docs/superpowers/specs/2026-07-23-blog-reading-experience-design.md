# ZHILI 博客阅读体验与性能优化设计

日期：2026-07-23  
状态：已确认，待实现

## 背景

当前博客使用 Hexo 6.3 与 Fluid 1.9.4。文章详情页采用桌面端 `2 / 8 / 2` 栅格：左侧为空白栏，正文占 8 列，右侧目录占 2 列。正文容器内部还保留左右各 10% 的内边距，因此宽表格的可用空间明显不足，多列内容被压成很窄的纵向文本。

本次优化包含三个目标：

1. 增加轻量、低干扰的动态宠物。
2. 扩大文章详情页正文空间，并改善宽表格阅读体验。
3. 在不牺牲阅读功能的前提下减少新增资源和非必要加载。

## 设计原则

- 不直接修改 Fluid 核心文件，优先通过 Hexo 根目录扩展和主题注入点实现。
- 不引入 Live2D、Canvas 引擎或前端框架。
- 不修改文章 Markdown 来适配某一种主题布局。
- 宠物和增强脚本失效时，正文、目录和表格仍可正常阅读。
- 遵循系统的减少动态效果设置，并优先保证移动端正文空间。
- 保留服务器工作区和 Fluid 主题中已有的未提交修改。

## 方案选择

### 采用：主题外扩展层

在 Hexo 根目录增加独立的注入脚本，通过 Fluid 的 `theme_inject` 接口加载自定义样式、交互脚本和宠物标记。静态资源放在 `source/` 下，由 Hexo 原样复制到生成站点。

优点：

- Fluid 升级时冲突较少。
- 功能边界清晰，可单独停用。
- 无需把服务器上现有的主题未提交改动纳入本次提交。

### 不采用：直接修改 Fluid 布局与样式

直接修改 `layout/post.ejs` 和 Stylus 文件可以获得完全控制，但会增加主题升级冲突，并要求提交当前主题子仓库状态。

### 不采用：Live2D 或第三方宠物组件

这类方案互动更丰富，但通常带来较大的模型资源、运行时脚本和外部依赖，与本次性能目标冲突。

## 组件设计

### Hexo 注入扩展

新增一个根目录 Hexo 脚本，职责仅包括：

- 在页面头部注入博客增强样式。
- 在页面底部注入增强脚本。
- 在文章页注入宠物的语义化 HTML。

注入失败不会改变原有文章 HTML 和 Fluid 导航、目录、评论功能。

### 动态宠物

采用内联或本地优化 SVG 表现蓝色机器人，不加载图片序列、Canvas 引擎或远程资源。

行为：

- 仅在宽度不小于 `992px` 的桌面页面显示。
- 固定在右下角，但与返回顶部按钮保持独立位置。
- 默认执行低频、低幅度待机动画。
- 悬停时挥手；点击时显示一句简短提示，提示自动消失。
- 不捕获宠物区域之外的鼠标或触摸事件。
- 在 `prefers-reduced-motion: reduce` 下停用位移动画。
- JavaScript 不可用时，宠物保持为不影响阅读的静态装饰。

资源目标：

- 宠物 SVG、CSS 和 JavaScript新增传输体积合计不超过 30 KB。
- 不产生第三方网络请求。

### 文章详情页布局

通过仅作用于文章页的增强类调整栅格，不改变首页、归档、分类和普通页面：

- `≥ 1200px`：正文区域 10/12，右侧目录 2/12。
- `992px–1199px`：正文区域 9/12，右侧目录 3/12。
- `< 992px`：维持 Fluid 当前单栏行为，不显示侧栏目录。
- 移除无内容的左侧桌面栏。
- 正文水平内边距改为响应式 `clamp()`，宽屏保留适度留白，窄屏不挤压正文。

如果无法仅靠附加样式稳定改写 Bootstrap 列宽，注入脚本可在文章页为现有三列添加语义类，但不得复制或替换正文内容。

### 宽表格

增强脚本在文章页加载后，为 `.markdown-body` 中尚未处理的表格增加滚动容器：

- 容器负责横向滚动，页面根节点不得出现横向溢出。
- 表格保持原生 `table`、`thead`、`tbody`、`th` 和 `td` 语义。
- 宽表格设置合理的最小宽度，避免单元格逐字换行。
- 普通窄表格仍按正文宽度显示。
- 滚动区域支持键盘聚焦，并提供可读的无障碍标签。
- 脚本重复执行时不得重复包裹同一张表格。
- 打印样式取消滚动容器限制，让浏览器正常排版。

### 性能优化

本次实施以下低风险优化：

- 新增增强脚本使用延迟加载，不阻塞正文首次渲染。
- 宠物只在符合桌面媒体条件时初始化。
- 动画仅使用 `transform` 和 `opacity`，避免持续触发布局计算。
- 正文图片在不破坏现有 Fluid 懒加载的前提下补充异步解码。
- 记录目标文章优化前后的 HTML 大小、关键本地资源体积、外部资源数量和总请求数量。
- 审查文章页加载的第三方脚本；只有确认在文章页无功能依赖时才移除，不为追求指标关闭目录、代码高亮、搜索或现有访问统计。

本次不包含 CDN 迁移、全站主题升级、构建工具替换和域名 HTTPS 改造。

## 数据流与失效处理

1. Hexo 构建时注册增强注入点。
2. 生成文章 HTML 时插入 CSS、延迟脚本和宠物标记。
3. 浏览器先渲染原有 Fluid 页面。
4. 增强脚本识别文章布局，添加作用域类并包装宽表格。
5. 仅在桌面媒体条件满足时初始化宠物交互。

失效策略：

- CSS 加载失败：保持当前 Fluid 布局。
- JavaScript 加载失败：表格保持原生展示，宠物为静态或不显示。
- SVG 加载失败：不显示破损占位图。
- 浏览器不支持相关媒体查询：采用静态、无动画表现。

## 测试与验收

### 构建与静态检查

- Hexo 干净构建成功且无新增错误。
- 生成的文章 HTML 只包含一次增强 CSS、脚本和宠物标记。
- 首页与归档页不注入文章宠物标记。
- 宽表格包装逻辑具有幂等性。
- 不修改或提交服务器现有的无关文件和主题未提交改动。

### 响应式检查

至少检查以下视口：

- `1440 × 900`：正文 10/12、目录 2/12、宠物可见。
- `1024 × 768`：正文 9/12、目录 3/12、宠物不遮挡目录。
- `390 × 844`：单栏正文、宠物隐藏、页面无整体横向滚动。

### 功能检查

- 目标文章七列表格可横向浏览，列内容不再逐字挤压。
- 宠物待机、悬停和点击反馈正常。
- 宠物不遮挡目录、正文、评论区和返回顶部按钮。
- 减少动态效果模式下无持续动画。
- 目录跳转、代码高亮、图片懒加载和返回顶部功能保持可用。

### 线上验证

部署后分别确认：

- 源分支提交已推送。
- Pages `master` 部署提交已更新。
- 正式文章返回 HTTP 200，并包含增强资源引用。
- 增强 CSS、JavaScript和宠物资源分别返回 HTTP 200。
- 浏览器桌面与移动视口的视觉表现符合验收标准。
- 报告优化前后的请求数和资源体积；无法可靠获取的指标标记为未验证。

## 发布边界

- 发布已获得用户授权。
- 只提交本设计和对应实现文件。
- 不发布或清理服务器中已有的其他未提交内容。
- 不把生成成功等同于远端推送、Pages 完成或线上生效；四个阶段分别验证。
