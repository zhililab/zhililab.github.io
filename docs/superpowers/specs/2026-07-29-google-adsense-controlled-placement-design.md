# Google AdSense 极简受控广告接入设计

日期：2026-07-29
状态：已确认，待实施计划

## 目标

在不改变 Hexo + Fluid + GitHub Pages 架构的前提下，为博客接入 Google AdSense，增加广告收入，同时保持技术文章的连续阅读体验和现有移动性能目标。

首期只使用一个受控广告位，不启用 Auto ads。AdSense 账号尚未注册或网站尚未获批时，网站不得显示空广告框，也不得发起 Google 广告请求。

## 已确认的产品选择

采用“A · 极简”版位：

- 只在博文详情页展示。
- 每篇文章最多一个响应式广告。
- 广告位于正文结束之后、评论区之前。
- 首页、归档、关于、隐私与 Cookie 政策等非博文页面不展示广告。
- 不在首屏、正文段落之间、代码块内、导航附近或浮层中展示广告。
- 不启用 Auto ads、锚定广告、插页广告或全屏广告。
- 文章可通过 frontmatter `ads: false` 单独关闭广告。

## 接入状态

广告模块分成三个明确状态。

### 未配置

没有真实 AdSense Publisher ID 或广告位 ID 时：

- 不输出广告容器。
- 不加载 Google 广告脚本。
- 不产生 Google 广告网络请求。
- 页面行为和性能与接入前一致。

仓库不得包含示例 Publisher ID、示例广告位 ID 或伪造的 `ads.txt` 记录。

### 审核中

AdSense 账号已创建、网站仍在审核时：

- 优先使用 AdSense 后台提供的 meta 标签或静态 `ads.txt` 完成网站所有权验证。
- 只写入后台实际提供的验证值。
- 不展示测试广告，不制造广告曝光或点击。
- 若 AdSense 明确要求审核代码，可增加独立的审核模式；该模式必须与正式广告开关分离，并在实施前核对后台提供的真实代码。

### 已获批

只有同时配置真实 Publisher ID、广告位 ID，并显式启用生产广告后：

- 输出一个文末响应式广告位。
- 广告接近视口或页面进入空闲阶段后再请求广告资源。
- 保留广告平台要求的原始参数和标记，不修改广告内容或点击行为。
- 广告加载失败、被拦截或 Google 网络不可用时，移除空容器，不阻塞正文和评论。

## 页面结构与交互

广告容器放在正文根节点之后、评论根节点之前。容器包含低调的“广告”标签，使广告与作者内容有明确区分。

广告与正文、评论区之间保留足够间距，避免误点。加载过程中使用稳定的最小高度控制布局偏移；确认无填充或加载失败后折叠容器。广告不会覆盖动态宠物、返回顶部、划线分享工具栏或评论输入区域。

移动端和桌面端使用同一响应式广告位，不创建额外的移动浮动广告。

## 配置边界

广告代码通过独立配置读取以下值：

- 是否启用生产广告。
- AdSense Publisher ID。
- 响应式广告位 ID。

这些值不得散落在文章 Markdown 或多个前端文件中。广告注入逻辑与当前阅读体验、性能管线保持模块边界；现有模块只提供稳定的文章和评论挂载位置。

敏感的 AdSense 登录密码、身份资料、地址、税务和收款信息不进入仓库。Publisher ID、广告位 ID 和 `ads.txt` 销售方记录属于公开发布标识，不是密钥，但只能使用账户后台提供的真实值。

## 隐私与合规

新增中文「隐私与 Cookie 政策」页面，并在全站页脚提供固定入口。页面至少说明：

- Google 及其他第三方可能使用 Cookie、Web Beacon、IP 地址或其他标识提供和衡量广告。
- 个性化广告可能基于访客在本站或其他网站的访问活动。
- 访客可前往 Google 广告设置管理或退出个性化广告。
- 评论系统和广告系统属于不同的数据处理方。
- 政策生效日期和后续更新方式。

面向欧洲经济区、英国、瑞士等流量，使用 AdSense 后台提供的 Google Consent Management Platform。生产启用前必须在 AdSense 的 Privacy & messaging 中完成相应地区的同意消息配置。

根目录静态 `ads.txt` 只在取得真实 Publisher ID 后创建，内容使用 AdSense 后台给出的完整记录。部署后验证 `https://www.zhililab.cn/ads.txt` 可直接访问。

该页面提供产品所需的透明披露，不替代针对个人具体情况的法律意见。

## 账号注册与职责

博客所有者负责：

- 使用自己的 Google 账号注册 AdSense。
- 提交真实姓名、地址、电话、身份、税务和收款资料。
- 在 AdSense 中添加 `www.zhililab.cn` 并发起网站审核。
- 不向任何人提供 AdSense 密码或验证码。
- 不点击自己的广告，不邀请他人点击广告。
- 在后台创建一个响应式展示广告单元，并提供 Publisher ID、广告位 ID 和 `ads.txt` 记录。
- 配置 Google CMP 并确认政策消息状态。

实施方负责：

- 增加可关闭的广告模块。
- 增加隐私与 Cookie 政策页和页脚入口。
- 根据后台真实值接入网站验证、`ads.txt` 和正式广告位。
- 完成自动化测试、Hexo 构建、隔离部署和正式站点验收。

## 性能策略

- 未配置和审核中状态不加载广告脚本。
- 正式广告脚本不进入首屏关键渲染路径。
- 广告在接近文末时加载，不与横幅、正文首图、关键 CSS 或评论资源竞争首屏带宽。
- 每篇文章只初始化一次广告脚本和一次广告请求。
- 不为广告增加新的框架依赖。

现有硬指标继续有效：

- 中端手机 + 普通 4G 冷缓存 LCP 不高于 2 秒。
- CLS 不高于 0.1。
- 正文图片进入视口后的显示目标保持约 300ms 内。

广告平台响应时间不计入首屏 LCP 的放宽理由。如果接入导致性能预算失败，应继续延迟广告资源或保持生产开关关闭。

## 测试与验收

### 自动化测试

- 无配置时，生成页不存在广告容器、AdSense 脚本和广告请求标记。
- 非博文页面不注入广告。
- 普通博文最多注入一个文末广告位。
- `ads: false` 的文章不注入广告。
- 缺少 Publisher ID 或广告位 ID 时保持关闭。
- 同一页面只加载一次 AdSense 脚本，只执行一次广告初始化。
- 广告节点顺序为正文之后、评论之前。
- 隐私与 Cookie 政策页面存在，页脚入口可访问。
- `ads.txt` 只接受格式正确的真实配置，不生成示例记录。

### 构建与浏览器验收

- 完整 Hexo 构建成功，现有测试无回归。
- 未配置账号的正式构建不产生 Google 广告请求。
- 获批后的广告位在桌面和移动端均不遮挡正文、代码、评论、宠物或划线分享工具栏。
- 广告拦截、无填充和 Google 网络不可用时页面仍可正常阅读，且不留下大块空白。
- 移动 4G 冷缓存 LCP、CLS 和正文图片显示继续满足既有预算。
- 正式页面、隐私页和 `ads.txt` 均通过 HTTPS 访问。

## 发布阶段

发布分两个阶段：

1. 审核准备：发布隐私页、页脚入口、关闭状态的广告模块，以及 AdSense 后台实际要求的网站验证材料。
2. 获批启用：取得真实 Publisher ID 和广告位 ID 后，补充 `ads.txt`，启用唯一文末广告位并重新完成性能与交互验收。

两个阶段都必须分别验证源码分支、Hexo 构建、Pages 部署、CDN 传播和正式域名；不得把“已提交”或“审核中”描述为“广告已开始产生收入”。

## 回滚

生产广告使用独立开关。发生性能、合规、布局或账户异常时，首先关闭生产广告，使生成页面不再输出广告容器和 Google 脚本；隐私政策页和历史 `ads.txt` 是否保留，依据 AdSense 账户状态单独决定。

回滚不得删除文章、评论数据或现有阅读体验功能。
